# vMix Integration — TennisTicker GFX

Live tennis & padel scores, names and serve indicators in vMix, for one court or
many courts at once, driven by two purpose-built endpoints on this server.

## 1. The data feeds (vMix Data Sources)

Both endpoints return **flat JSON** designed for vMix Data Sources — every value
is a string, no nesting, stable column names.

### `/api/v1/vmix` — one row per court

The most relevant match per court is chosen automatically
(**live → next upcoming → last completed**). Ideal for a single-court title with
row selection, or for tickers that cycle rows.

| Column | Example | Notes |
|---|---|---|
| `court` | `Court 1` | |
| `status` | `LIVE` / `UPCOMING` / `COMPLETED` | suspended etc. pass through raw |
| `p1_name`, `p2_name` | `Juan LEBRON` | proper-cased full name |
| `p1_surname`, `p2_surname` | `LEBRON` | ALL CAPS |
| `p1_country`, `p2_country` | `ESP` | IOC 3-letter |
| `p1_serve`, `p2_serve` | `●` or empty | ready to map straight into a text field |
| `p1_points`, `p2_points` | `40`, `AD`, `00` | current game, live only |
| `p1_set1`…`p1_set5` (+ p2) | `6` | empty until the set has games |
| `set1_tb`…`set5_tb` | `7` | tiebreak points, empty if none |
| `p1_games`, `p2_games` | `3` | games in the set currently in play |
| `p1_sets_won`, `p2_sets_won` | `1` | handles 7-6 TB and 10-point match TB |
| `sets_summary` | `6-4 3-2` | one-field score string |
| `current_set`, `matchid`, `matchname`, `tournament`, `schedtime`, `winner_name` | | |

Filter to one court: `/api/v1/vmix?court=2` (exact token — `2` will not match `Court 12`).

### `/api/v1/vmix/wide` — one row, all courts (multi-court board)

Every column above, prefixed per court slot: `court1_p1_name`,
`court1_p1_serve`, `court2_p1_set1`, … plus a shared `tournament` column.
Slots show 3 sets (padel / best-of-3). Unused slots are blank strings, so field
mappings never break when a court goes quiet.

Options:

- `?courts=6` — number of slots (1–8, default 4)
- `?order=Court 1,Centre Court,Court 3` — explicit slot order; default is
  natural sort (Court 1, Court 2, … then named courts)

## 2. Multi-court title: `TennisTicker_MultiCourt.xaml`

A ready-to-use **vMix XAML title** (1920×1080, transparent) showing **4 courts
at once** — court name, status, both players, serve dot, 3 set boxes and a
highlighted points box per player. Every text field is named **identically to
its `/api/v1/vmix/wide` column** (`court1_p1_name`, `court3_p2_serve`, …), so
mapping is mechanical.

### Setup

1. vMix → **Add Input → Title / XAML** → select `TennisTicker_MultiCourt.xaml`.
2. **Settings (gear) → Data Sources → Add → JSON**
   - URL: `https://scores.nkpa.co.uk/api/v1/vmix/wide`
   - Update interval: 1–2 s (the server itself polls TennisTicker every ~5 s)
3. Open the **Title Editor**, and for each field choose the Data Source column
   with the **same name** as the field.
4. Done — names, sets, points and the serve dot now update live for all courts.
   Tennis and padel both flow through unchanged (padel match tiebreaks like
   `10-8` are handled in `sets_won`).

## 3. About GT (.gtzip) titles

`.gtzip` files are packages produced by **vMix GT Title Designer**; the internal
format is generated by the designer and is not reliably hand-authorable, so a
hand-written one would likely fail to load. Two good options:

- **Use the XAML title above** — it is a first-class vMix title format and works
  with Data Sources exactly like a GT title.
- **Build the GT title once in GT Title Designer** (for GT animation features):
  create text fields named exactly `court1_p1_name`, `court1_p1_serve`,
  `court1_p1_set1..3`, `court1_p1_points` (and `p2`, courts 2–4, `tournament`,
  `court{n}_court`, `court{n}_status`), save as `.gtzip`, then map fields to the
  `/api/v1/vmix/wide` data source as in step 3 above. Because the names match
  the feed columns 1:1, the mapping takes minutes and the same feed drives both
  titles.

For a **single-court GT scoreboard**, point the data source at
`/api/v1/vmix?court=1` instead and name fields without the `courtN_` prefix
(`p1_name`, `p1_serve`, `p1_set1`, …).

## 4. Serve indicator script (`scripting`)

The polling VB script now reads the serve fields directly from the vMix title
input after vMix has populated its data source. Expose `p1_serve` and
`p2_serve` on the scoreboard input, and the script will use those fields to
toggle `SERVE_1.source` and `SERVE_2.source`.
