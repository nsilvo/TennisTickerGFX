🎾 Live Score Scraper — Help & Data Reference

This guide explains the API, fields, and includes an in-browser explorer.

⬅ Back to Dashboard

🛠 API Reference

  • GET /api/v1/scores — all cached matches; response includes tournament_id, last_updated, refresh_interval_seconds, match_count, matches[].
  • GET /api/v1/scores/court/<court_number> — same as above, filtered to one court.
  • GET /api/v1/match/<match_id> — single match lookup; 404 if not found.
  • GET /api/v1/schedule — order of play for every court (LTA schedule merged with TennisTicker matches); ?date=today|upcoming|all|YYYY-MM-DD.
  • GET /api/v1/schedule/court/<court> — one court's event list as a flat array for vMix (slot, time, event, round, p1_full_name, p2_full_name, status, score, matchid…). Accepts the TennisTicker or LTA court name, or just the number.
  • GET/POST /api/v1/manual/<match_id> — commentator manual scoring (actions: start, point, undo, server, games, rules, resync, stop). The most recently changed of the feed and manual score is the one shown.
  • GET or POST /api/v1/tourid/<new_tour_id> — switch the TennisTicker feed tournament being scraped (numeric only). Requires an admin login session; returns 403 otherwise. Which match tournaments are shown is set on the Config page.

Examples:

curl -s http://localhost:5000/api/v1/scores | jq '.match_count, .last_updated'
curl -s http://localhost:5000/api/v1/scores/court/3 | jq '.matches[] | {matchid, court, matchstatus}'
curl -s http://localhost:5000/api/v1/match/12345 | jq
curl -X POST http://localhost:5000/api/v1/tourid/7140 | jq

Notes: all endpoints return JSON; errors include an error field; timestamps are Unix seconds in the match objects and a formatted string in last_updated.

📑 API Output Fields

Top-level (GET /api/v1/scores)

  • status: success or error text.
  • filter: description of court filter applied.
  • tournament_id: current tournament being scraped.
  • last_updated: latest match timestamp (formatted string).
  • refresh_interval_seconds: scraper interval.
  • match_count: number of matches returned.
  • matches: array of match objects (see below).

Match object (common fields)

  • matchid (string): unique match id.
  • matchname (string): display title.
  • court (string): court label/number.
  • matchstatus (string): IN PROGRESS, COMPLETED, UPCOMING/PLAN, TEST.
  • timestamp (int): Unix seconds of last update for this match.
  • is_plan (int): 1 if planned/upcoming; 0 otherwise.
  • schedtime (string): scheduled start time (may be empty).
  • winner (string/int): winner flag; winner_name (string): name if completed.
  • player1, player2: player display names.
  • player1_country, player2_country: 3-letter country codes.
  • player1_full, player2_full, player1_surname, player2_surname: raw name fields as provided.
  • sets_played_count: number of sets reported (may be 0 for planned).
  • game1, game2: current game score for p1/p2 (live only).
  • player2serve: "1" means p1 serving, "2" means p2 serving.
  • lastservetype: raw serve type flag (if present).
  • tournid, eventid, extmid: source identifiers.
  • cam, cameraurl, camerarooturl: camera metadata if provided.
  • stats_general, stats_match: stats availability flags.

Set fields

  • For each set N (1..11): setN_p1, setN_p2 are set games; setN_tb is tie-break value when relevant.

Single-match endpoint

  • GET /api/v1/match/<match_id> returns { status, match } or 404 with { error }.

Tournament switch

  • GET/POST /api/v1/tourid/<new_tour_id> returns { status, message, new_tournament_id }; errors include { error } (403 without an admin session).

🎬 Selecting a Match for Scoreboard/Bug

Overlays pick a match in this order:

  • ?court=5 in the bug URL targets the best match on that court.
  • ?matchid=123 in the URL forces that match (if it exists).
  • No matchid + exactly one live or warm-up match ⇒ that match is used automatically.
  • Multiple live matches without matchid ⇒ overlays may stay empty; pass a matchid.

Examples:

Scoreboard: /caspar/scoreboard/?matchid=12345
Bug:        /caspar/bug/?court=5

# - Scoreboard button: adds matchid automatically

🎛 vMix Serve Script Guide

The vMix script in this repo (file: vmix/scripting) automatically toggles serve indicators in your scoreboard title based on live API data.

What you need in vMix first

  • A title input named SCOREBOARD (or change SCOREBOARD variable in script).
  • A text field in that title called MATCHID.Text containing the current match ID.
  • Two image layers named SERVE_1.source and SERVE_2.source.

How to install and run in vMix

  1. Open vMix and go to Settings → Scripting.
  2. Create a new script and paste the contents of vmix/scripting.
  3. Set SCOREBOARD to your title input name if different from default.
  4. Set VMIX_DATA_URL to your vMix JSON feed, for example https://scores.nkpa.co.uk/api/v1/vmix or your local endpoint.
  5. Save and click Start for the script.
  6. Update MATCHID.Text on the scoreboard input to the match you want to track.

What the script is doing

  • Runs an infinite loop and polls every 500ms.
  • Reads MATCHID.Text from the SCOREBOARD title input.
  • Calls /api/v1/vmix to get the vMix JSON feed.
  • Finds the row whose matchid matches the scoreboard input.
  • Reads p1_serve / p2_serve from that row.
  • If value is 1: shows SERVE_1.source, hides SERVE_2.source.
  • If value is 2: hides SERVE_1.source, shows SERVE_2.source.
  • For missing/invalid value: hides both serve indicators.
  • Only performs visibility updates when the serve value changes, to reduce unnecessary commands.

Troubleshooting

  • If console shows Scoreboard input not found, check the input name matches SCOREBOARD.
  • If console shows Match ID not found, ensure MATCHID.Text exists and is populated.
  • If indicators never change, verify API reachability by opening /api/v1/vmix in a browser and checking the row for matchid plus p1_serve / p2_serve.
